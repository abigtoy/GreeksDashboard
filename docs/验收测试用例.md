# 验收测试用例
> GreeksDashboard v1.3 基线验收，来源：审查意见 `审查意见260917.md` P2-4

## 测试环境前置条件

- CTP 连接正常（能在 09:00/13:00/21:00 收到行情）
- 结算单目录有 `full_{date}.json`（至少 T-1 和 T-2 各一份）
- 快照目录有历史快照文件
- 服务启动：`C:/veighna_studio/python.exe run_server.py`（项目目录 `C:/qproj`）

---

## 场景一：多空持仓混合

**目的**：验证方向铁律、混合仓守恒计算、OffsetFlag 归因

**步骤**：
1. 同一合约（如 `IC2609`）同时持有多头和空头
2. 昨持有多头 2 手，今开空头 1 手（开仓）
3. 今日平多 1 手（平昨，OffsetFlag=CloseYesterday）
4. 观察 dashboard 中 `IC2609_多` 和 `IC2609_空` 分别正确显示

**验收标准**：
- [ ] 多头和空头的 `direction` 字段分别正确（`多`/`空`）
- [ ] `IC2609_多` 的 pnl_today/pnl_history 与 `IC2609_空` 独立计算，互不影响
- [ ] `total_pnl_today` = Σ 各合约 pnl_today（含 realized + unrealized）
- [ ] 日志无 `fifo_fallback`（OffsetFlag 正常时）

---

## 场景二：今开今平（当日回转）

**目的**：验证平今仓的 realized PnL 正确累加

**步骤**：
1. T 日开盘后，新开 `MO2609-C-7000` 多头 1 手（OffsetFlag=Open）
2. 同日平仓（OffsetFlag=CloseToday），成交价 > 开仓价
3. 持仓 tree 中该合约消失（volume=0）

**验收标准**：
- [ ] 该合约不出现在持仓 tree 中
- [ ] `total_pnl_today` 包含该笔 realized PnL（全为已实现）
- [ ] `_realized_pnl_cache` 中有对应记录

---

## 场景三：平今/平昨 分别计算

**目的**：验证 OffsetFlag 区分 CloseToday/CloseYesterday 的归因逻辑

**步骤**：
1. 同一合约（如 `IF2609`）昨仓 3 手
2. 今日平今 1 手（CloseToday）+ 平昨 1 手（CloseYesterday）
3. 剩余 1 手昨仓（未平）

**验收标准**：
- [ ] 平昨仓位 cost_basis = settlement_cost_dict，pnl_today 基准 = Mark_T-1
- [ ] 平今仓位 cost_basis = 今日开仓均价，pnl_today 基准 = 今日开仓价
- [ ] `_realized_pnl_cache` 分别记录两条 realized 条目

---

## 场景四：全平仓后服务重启

**目的**：验证 trade_cache 幂等 + session_state 恢复

**步骤**：
1. 某合约全部平仓（持仓 volume=0）
2. 触发快照保存（空仓快照，含 `snapshot_kind: "empty"`）
3. 服务重启
4. 重连 CTP

**验收标准**：
- [ ] 重启后该合约不出现在持仓 tree
- [ ] realized PnL 不丢失（通过 session_state.json 恢复 `_realized_pnl_cache`）
- [ ] `snapshot_kind: "empty"` 快照覆盖前一个非空快照
- [ ] `allocation_source` 字段存在且值为 `ctp_offset` 或 `fifo_fallback`

---

## 场景五：缺结算单

**目的**：验证降级链路（无结算单时 settle_key=0，pnl_daily 不崩溃）

**步骤**：
1. 删除 `结算单/full_{T-1}.json`
2. 重启服务
3. 连接 CTP，观察 pnl_daily

**验收标准**：
- [ ] 服务不崩溃（降级为 position.price 或 0）
- [ ] 日志有 `warning: settlement_file_missing` 记录
- [ ] pnl_history/pnl_today 不为错误值

---

## 场景六：缺行情（未开盘）

**目的**：验证 not_opened/stale 状态

**步骤**：
1. 某合约 T 日尚未收到任何 tick
2. 查询 `/api/dashboard` 中该合约的 market_status

**验收标准**：
- [ ] `market_status` = `"not_opened"`（未开盘）
- [ ] `price_source` = `"none"`
- [ ] Greeks 全为 null，不为 0

---

## 场景七：夜盘跨日

**目的**：验证 TradingDay 切换、空仓快照、持仓清空

**步骤**：
1. T 日 21:00 夜盘开盘，持仓快照保存（session=N）
2. T+1 日 09:00 早盘开盘，TradingDay 从 T 切换到 T+1
3. 观察 opened_contracts/trade_cache 清空

**验收标准**：
- [ ] 快照文件名从 `data_snapshot_T_N.json` 变为 `data_snapshot_T+1_A.json`
- [ ] `opened_contracts` 和 `_realized_pnl_cache` 在切换时清空
- [ ] 空仓快照（含 `snapshot_kind: "empty"`）正确覆盖前一个非空快照

---

## 场景八：结算单汇总与明细差异告警

**目的**：验证双策略优先级 + 差异告警

**步骤**：
1. 构造 `full_*.json`，其中 `positions_summary` 和 `positions_detail` 同一合约价格差异 > 5%
2. 加载结算单
3. 检查日志

**验收标准**：
- [ ] 最终 settlement_cost_dict 值为汇总（positions_summary）的值
- [ ] 日志有 `warning: settlement_summary_detail_mismatch` 记录差异值
- [ ] 无 `KeyError` 或字段缺失错误

---

## 场景九：双策略优先级（汇总缺失用明细兜底）

**目的**：验证明细兜底逻辑

**步骤**：
1. 构造 `full_*.json`，只有 `positions_detail`，无 `positions_summary`
2. 加载结算单

**验收标准**：
- [ ] settlement_cost_dict 从 `positions_detail` VWAP 自算填充
- [ ] 所有 key 格式为 `{sym}_{direction}`

---

## 场景十：B1/B2 数值验证

**目的**：验证 L1 重复累加（double-count）修复和 Gamma cash 缩小100倍修复

**步骤**：
1. 连接 CTP，持仓包含 IF/IO 品种（多合约）
2. 对比 v1.3 前后 Greeks 数值

**验收标准**：
- [ ] L1 品种（如 IF）的 Greeks 为 Σ L2 月份，不再是 2×（B1 修复）
- [ ] gammacash 数值不再异常偏小 100 倍（B2 修复）

---

## 场景十一：CTP 重连幂等

**目的**：验证掉线重连后 trade_cache 不重复

**步骤**：
1. CTP 断开（网络模拟）
2. 重连
3. 同一批 trade 再次推送
4. 检查 `_seen_trade_ids` 和 `_trade_cache`

**验收标准**：
- [ ] 重复 trade_id 不重复进入 `_trade_cache`（幂等）
- [ ] `dedup_key` 存在且唯一

---

## 场景十二：IV 反推校验

**目的**：验证理论边界校验和 iv_source 标注

**步骤**：
1. 某期权合约 bid/ask 价差超过合理阈值
2. 检查该腿 Greeks 结果

**验收标准**：
- [ ] `iv_source` 字段存在且值合理（`adjust_price`/`atm_median`/`invalid_spread`）
- [ ] Greeks 计算不抛出异常
- [ ] 日志有 IV 回退相关记录

---

## 场景十三：P1-12 session_state 重启后今仓成本归零

**目的**：验证 trade_cache 重启后降级行为

**步骤**：
1. 日内某合约今仓成交，有完整 trade_cache
2. 服务重启
3. `session_state.json` 中 trade_cache 恢复
4. 观察该合约今仓 cost_basis

**验收标准**：
- [ ] 今仓 cost_basis 归零（降级处理），非原始成交价
- [ ] 日志有 `warning: trade_cache_recovered_as_yesterday_position` 记录
